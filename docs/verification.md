# 验证记录

发布前做过什么、没做过什么，都在这里。**测试通过不是安全审计，也不是容量保证。**

## 已做

| 项目 | 命令 / 方式 | 结果 |
|---|---|---|
| 语法检查 | `node --check` 遍历全部 `.mjs` | 0 错误 |
| 依赖 | 检查 import | 服务端只用 Node.js 内置模块；前端零构建；`plugins/` 里的宿主 SDK 不参与服务启动 |
| 本地启动 | 全新副本 `node server.mjs` | 正常监听，自动生成 `data/` 下的注册码、口令、房间库 |
| 未带口令访问 | `GET /` 不带 `?k=` | 返回 401（符合设计） |
| 群主注册 | 全新 `data/` 上 `POST /api/auth/register` | 正常返回（此路径曾因 `db.presence` 未初始化崩溃，已修） |
| 房间流程 | 建房 → 派任务 → 报告 → 互评 → 收敛 | 消息与卡片按顺序呈现 |
| 桌面与窄屏 | 1440×900 / 430×860 | 布局正常，窄屏不横向溢出 |
| 现有测试套件 | `node tests/run-all.mjs`（在副本、独立端口） | 见下方说明 |

测试套件在发布前的副本上跑过，纯逻辑用例全过；集成用例需要先启动副本服务，并会让测试房间归档或解散，所以**只在独立副本上跑**，不要指向日常在用的实例。

## 没做

- **没有独立安全审计**。鉴权、邀请码、控制面执行 gate 命令等路径只做过功能性验证。
- **没有容量与并发测试**。多实例、多机器、跨地域都没有验证。
- **没有部署自动化**。没有容器镜像、CI 流水线、监控、备份与密钥轮换。
- **没有公网实例**。本次发布不附带在线演示；隧道脚本只在本机验证过连通。
- **跨平台未验证**。只在 Windows + Node.js 22.22.3 上跑过。

## 已知脆弱点

- 关键状态存在本地 JSON / JSONL 文件里，采用临时文件替换写入，但没有跨文件事务、分布式锁或多实例协调。
- 会话与唤醒治理依赖宿主接口和本机会话目录；换宿主或换机器需要改适配，不是配置就能迁。
- 快速隧道域名每次重启都会变，断线不会自动恢复服务。

这些也是 README「当前边界」一节的依据。
